# Слои приложения

Зависимости направлены строго сверху вниз. Нижние слои не знают о верхних.

```
Router (тонкий адаптер)
  ↓ вызывает ТОЛЬКО
Service (оркестратор, единственная точка входа)
  ↓ использует
Unit of Work (transactional boundary, предоставляет репозитории)
  ↓ содержит
Repository (все операции с хранилищем)
  ↓ маппит на
Domain (бизнес-логика, entities, value objects — чистые dataclass)
```

## Router

Тонкий адаптер. Принимает HTTP-запрос, валидирует через Pydantic-схемы, вызывает сервис, возвращает ответ. Трансформирует доменные ошибки в HTTP-ответы.

## Service

Единственная точка входа для бизнес-логики модуля. Обычный класс с конструктором. Оркестрирует вызовы и делегирует выполнение домену. Не содержит бизнес-логики, вычислений и деталей работы с хранилищем. Подготавливает ответ для роутера.

## Unit of Work

Transactional boundary. Общий для всех модулей, живёт в `common/`. Владеет сессией, предоставляет доступ ко всем репозиториям (`uow.users`, `uow.billing`). Гарантирует атомарность: commit или rollback.

## Repository

Инкапсулирует все операции с хранилищем (чтение и запись). Работает через query builder. Возвращает и принимает только доменные сущности.

## Domain

Ядро. Чистые Python dataclass-ы: entities (с идентичностью) и value objects (неизменяемые, без ID). Вся бизнес-логика и правила валидации живут здесь. Никаких зависимостей от инфраструктуры.

## Версионирование API

- Версия в URL: `/api/v1/...`, `/api/v2/...`
- Каждая версия — отдельный FastAPI router
- При выходе новой версии предыдущая продолжает работать
